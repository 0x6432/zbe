# Extern/GOT foundation — work in progress

This is an unreviewed draft, based on integration draft `3890562118b85be550dcc19f6c400414d3f8672a`. That base has not passed its fresh local integration gate or terminal audit. Its exact-commit rewrite and standard CI passed, but nightly failed in Zig-master and programs jobs. This branch is not production acceptance or a complete extern/GOT implementation.

Draft rewrite CI on `cbf14a5eb64ac5405da17b937fc27fecba950e89` failed in all three compiler modes in the combined native-execution step. Public job status does not identify the failing command. In a local Debug reproduction of that exact commit, `native_symbol_check.py` failed because it still expected the newly supported `extern $target` syntax to be rejected; this is a reproduced cause locally, not authenticated hosted-log evidence. The draft updates that check, splits the new smoke steps for diagnosis and improves missing-tool reporting; these changes have not yet passed CI.

Current work adds a module-owned `got_symbol` IR operand, conservative decoded-symbol eligibility and an allocation-free eligibility scan after generic and aggregate checks. Scalar-only modules are scanned before the existing empty-plan return. Contextual extern value and call syntax and dedicated/wrapped call-target identity are implemented in the draft. The interpreter refuses reached GOT operands/calls. The AMD64 emitter now loads addresses from GOTPCREL and performs indirect calls; this new implementation is still unreviewed and not fully validated.

Focused tests covered operand, eligibility, call identity, parser behavior and allocation cleanup: 8/8 passed separately in Debug, ReleaseSafe and ReleaseFast. The naming helper also passed focused Debug tests. A Debug native smoke passed 32 combinations (8 code-generation options, 2 linker settings, provider/preload), including scalar and two small/large record call cases; a GOT-slot-address mutant was rejected. These are not the full loader or compatibility ledger. Full three-mode testing, the existing compatibility matrices, independent reviews, secondary calibration audit, terminal audit and exact-commit CI for this new tree remain outstanding. No release, canonical advancement, ABI parity or complete compiler claim is made.

Independent static review of `a7997a535e9e7f121833bac49b85ac914ebd6873` identified incorrect interpreter refusal for new call targets and missing declaration-position diagnostics. This work-in-progress corrects both, with a 31-case exact-byte-span diagnostic table and ordering tests for standalone/module-owned calls, poisoned GOT arguments/ENV, step/depth limits and both target forms. Ten focused tests passed in Debug, ReleaseSafe and ReleaseFast under the shared lock; broader coverage and independent review of the corrected tree remain outstanding. Earlier focused runs were not consistently taken under the specified shared lock and are not acceptance evidence.

A separate focused native ABI smoke exercises seven GP arguments, nine FP arguments, mixed GP/FP overflow, a scalar ENV call and a nine-FP variadic call against independent C/assembly providers, both ordinary and preempted, with assembly AL/register capture plus AL=0 and ENV-clobber runtime negative controls. An earlier AL mutant used a C varargs consumer and was discarded as unreliable; the replacement does not consume invalid varargs. Default and all-flags Debug cases passed; other modes/options and the full ABI ledger are not yet proven. The focused smoke tools were registered in draft rewrite CI at `cbf14a5`; the combined native step failed, with the specific command not yet identified.

Independent focused safety tests cover selected/whole planning scope, error precedence, nonnative interpreter paths, local-object refusal, iterator order, SSA/liveness/interference and folding. Debug and ReleaseSafe agent runs passed before integration; they do not replace full coverage or independent review of this combined tree. An isolated loader harness recorded 12 default-option and 12 full-option combinations including explicit PIE/non-PIE and provider/DT_NEEDED/preload binding; its ordinary-LEA mutant was rejected at link, not runtime, and ledger certification remains open. Both loader settings were registered in draft CI, but the failed combined step does not establish that they ran. A separate CLI smoke checks absent and preexisting output across five failure classes and success, in default/full Debug options.

A focused Debug allocation-frontier test injects failures at every observed generic-validation allocation and the next boundary, for scalar, record-relevant, unreachable and both call-target forms, across detached plans, whole-module plans and emission. It verifies name refusal before further allocation and retries the same module. Additional focused tests retry the same symbol pool and call builders after allocation failures and sweep successful emission allocation failures; those tests passed in Debug, ReleaseSafe and ReleaseFast in a separate clone. This is not the complete O01–O10 ledger. Loader subprocesses now use an explicit minimal environment, and an ordinary-LEA link failure is classified only when the expected PC32 diagnostic is present; it remains inconclusive for M01.

An independent focused record harness covers SSE, mixed INTEGER/SSE, union, and dynamic-stack/record pressure with provider/preload and an SSE result-lane control. Default and full options passed on a ReleaseSafe compiler before integration. It was registered in draft CI at `cbf14a5`; that combined step failed without an identified hosted failing command. Guard pages, target-scheduling defect control and the full record ledger remain open.

Additional focused symbol identity and operand-site tests passed in Debug, ReleaseSafe and ReleaseFast. The site matrix covers 30 parse/IR/validation/emission witnesses, not linked execution or real descriptor contents; its allocation-size witness is unreachable. A local Debug-compiler run passed 312 legacy and focused smoke invocations across all eight option combinations after the stale symbol rejection was corrected. The general smoke passed 32 option/link/provider cases, and the loader smoke passed 12 cases each in default and full options. Its ordinary-LEA link rejection is not a runtime witness. The combined suite passed 555/555 tests in each of Debug, ReleaseSafe and ReleaseFast before the last test-only review refinements; the affected focused tests were then rerun in all three modes. These checks are not a substitute for the full acceptance ledger.
