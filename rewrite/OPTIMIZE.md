# Conservative integer constant folding

`optimize.foldIntegerConstants(allocator, function)` validates scalar SSA, allocates invocation-owned facts, then performs a single source-order traversal. It returns the number of rewritten instructions. All fallible setup precedes mutation; allocation/validation failure leaves that function's instructions unchanged. Module-wide transactionality is not promised.

Operand-preserving integer neutral identities are also simplified in the same opt-in pass, after complete constant folding: `x+0`, `0+x`, `x-0`, `x*1`, `1*x`, `x|0`, `0|x`, `x^0`, `0^x`, `x&allones`, `allones&x`, and shifts by a known count masked to zero at the operand width. The replacement copies the ORIGINAL operand (including low-word projections and symbol addresses), so operand resolution and its refusals remain observable. Known source-order facts can prove the neutral constant. No operand-dropping identities (`x*0`, `x&0`, `x-x`, `x^x`), division/remainder identities or floating identities are added. No speedup is claimed.

Known integer arithmetic, shifts, integer comparisons, extensions, raw bitcasts, copies and sign-bit negation can become constant copies. Integer zero divisors and signed-minimum/minus-one pairs remain executable binary instructions: they are not replaced by arbitrary values or removed. Pure scalar bit-pattern semantics are shared with the evaluator in `semantics.zig`, while expected results remain independently generated by Python.

Floating arithmetic, floating comparisons and precision widening are deliberately not folded, because their floating-environment effects are outside this pass's assumptions. Raw floating copies/casts/sign flips preserve bits without arithmetic. Parameters and phi results remain unknown; no fixed point, path selection or reachability inference is attempted. A definition later in layout may therefore prevent a safe-but-optional fold.

The pass preserves value/block IDs, definition backlinks, instruction counts, CFG, phi inputs and terminators. It does not delete dead instructions, compact frames, simplify branches, optimize loops, allocate registers or establish full QBE optimizer parity.

The CLI is opt-in:

```sh
./zig-out/bin/zbe-native --fold-integers input.ssa output.s
```

Without the flag, the new driver retains its unfurled path. This option is not a legacy `-O` level and does not change the old compiler's compatibility modes.

Tests check 2,444 independently generated constant arithmetic/shift/comparison/division results, chained propagation, low-word branches, conservative layout order, invocation isolation, unchanged floating operations, preserved arithmetic faults, invalid SSA, failure atomicity and cleanup. Both native harnesses can run with `--fold-integers`; the integer harness checks dynamic and compile-time arithmetic-fault operands separately.

The separate `--reuse-stack-homes` option runs interference coloring after folding; it does not expand what this folding pass optimizes. The flags may also be combined with the limited `--callee-saved-homes` option, in any order; all eight flag combinations are checked by the native harnesses. See STACK-HOMES.md.
