# Continuation from 4f9080b — guarded scalar varargs runtime witness

The base is `4f9080b5d5e197df9d0ed2d89ac49ea1e7b7bb01`. This is a partial runtime witness, not N11 completion or gate acceptance. The design remains unratified and the integration gate remains **HELD**.

`extern_got_varargs_runtime.py` builds a separate IL subject DSO and two PIC C providers, and runs a C client both PIE and non-PIE. For each of the eight existing optimization combinations, it checks normal and LD_PRELOAD binding: 32 successful invocations. Each run verifies provider selection, the dynamically resolved descriptor address and the IL materialized address before use; checks immediate guard words; compares scalar word/long/double values and the final descriptor bytes with an independently `va_start`/`va_copy`-initialized live C `va_list`; and exercises an IL `vastart` followed by scalar reads while its own variadic frame is live. Seven GP variadic arguments and ten doubles cross both register banks into overflow storage. Descriptor storage is reinitialized before reuse; the descriptor left by the IL frame is not dereferenced after return. Single-precision `vaarg` is intentionally not run via C varargs, which promote `float` to `double`; aggregate vaargs remain outside the contract.

The harness checks a `R_X86_64_GLOB_DAT` relocation for `n11_vlist`, rejects COPY/TEXTREL and SYMBOLIC in the built objects, cleans the subprocess environment, and uses the shared bounded verification lock. Sixteen runs with an intentionally wrong expected preloaded provider were rejected at the identity assertion; these are fixture controls, not M01 mutation calibration. An isolated IL-only control that adds one to the correctly consumed word was rejected by the live-descriptor C oracle; it is a fixture-sensitivity check, not a compiler mutant or M01. The added CI step runs this bounded witness, not the required full bundle.

Local evidence was produced with a ReleaseSafe compiler built from exact base `4f9080b` using pinned Zig and the repository's resource policy, with no in-progress or queued hosted branch run at launch. `/data/zbe-vaarg-exploration/matrix-04` retains fixture copies, compiler/fixture SHA-256 hashes and a command journal with outputs/exits and the cleaned environment. The initial matrix attempt (`matrix-01`, duplicated `matrix-02`) correctly failed because the non-PIE C client's `stderr` reference created an unrelated COPY relocation; the fixture changed to `dprintf(2, ...)`, and the stronger no-COPY check was retained. This working-tree test was not a hosted exact-commit CI run for this continuation commit. Local scratch evidence is not independently protected gate evidence.
