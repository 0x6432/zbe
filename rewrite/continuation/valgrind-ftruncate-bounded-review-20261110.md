## Selected wrappers and conditional route

- The Valgrind AMD64 table selects the generic [`truncate` and `ftruncate` wrappers](https://github.com/unofficial-mirror/valgrind/blob/8d3c8034b87db7b1d47285b053a05e6ad277c0d1/coregrind/m_syswrap/syswrap-amd64-linux.c#L563-L565). The complete [`ftruncate` PRE wrapper](https://github.com/unofficial-mirror/valgrind/blob/8d3c8034b87db7b1d47285b053a05e6ad277c0d1/coregrind/m_syswrap/syswrap-generic.c#L3496-L3501) marks `SfMayBlock` and reads its FD and length arguments, but does not call `fd_allowed` or set a failure status. The preceding provenance note traces the conditional blocking dispatch through `do_syscall_for_client` to the guest syscall assembly site. This is **not** the shared generic logger-write instruction.
- The compared Linux [`ftruncate` path](https://github.com/torvalds/linux/blob/8bb7eca972ad531c9b149c0a51ab43a417385813/fs/open.c#L155-L203) uses `fdget`, requires a regular inode and `FMODE_WRITE`, rejects append-only inodes, performs a security hook, and calls `do_truncate`; additional filesystem, LSM and policy restrictions may apply. For a known still-open numeric FD referring to a writable regular log file, if those checks and the actual policy permit the call, a guest-supplied length may change the log file's size without an ordinary write or an O_RDWR alias. The logger's documented `O_WRONLY` mode satisfies the cited write-mode condition, but does **not** by itself establish an open live regular sink, knowledge of its FD, or successful truncation. Log buffering, offsets, races and later writes affect the observable result. A file-size change is not proof of arbitrary-byte forgery or actual gate compromise.
- The path-based [`truncate` wrapper](https://github.com/unofficial-mirror/valgrind/blob/8d3c8034b87db7b1d47285b053a05e6ad277c0d1/coregrind/m_syswrap/syswrap-generic.c#L3503-L3510) marks the path memory and does not apply an FD check. The compared kernel's [path-based checks](https://github.com/torvalds/linux/blob/8bb7eca972ad531c9b149c0a51ab43a417385813/fs/open.c#L69-L110) include regular-file, mount, inode-write, append, lease and security checks; reaching the relevant path and satisfying those checks are unknown.
- Contrast: selected AMD64 table entries for [`fallocate`](https://github.com/unofficial-mirror/valgrind/blob/8d3c8034b87db7b1d47285b053a05e6ad277c0d1/coregrind/m_syswrap/syswrap-amd64-linux.c#L815), [`pwritev`/`pwritev2` and `copy_file_range`](https://github.com/unofficial-mirror/valgrind/blob/8d3c8034b87db7b1d47285b053a05e6ad277c0d1/coregrind/m_syswrap/syswrap-amd64-linux.c#L828-L869) route to wrappers that call `fd_allowed`: [`fallocate`](https://github.com/unofficial-mirror/valgrind/blob/8d3c8034b87db7b1d47285b053a05e6ad277c0d1/coregrind/m_syswrap/syswrap-linux.c#L2196-L2215), [`pwritev` shared helper](https://github.com/unofficial-mirror/valgrind/blob/8d3c8034b87db7b1d47285b053a05e6ad277c0d1/coregrind/m_syswrap/syswrap-linux.c#L6212-L6222) reached by [both wrappers](https://github.com/unofficial-mirror/valgrind/blob/8d3c8034b87db7b1d47285b053a05e6ad277c0d1/coregrind/m_syswrap/syswrap-linux.c#L6239-L6294), and [`copy_file_range` for both descriptors](https://github.com/unofficial-mirror/valgrind/blob/8d3c8034b87db7b1d47285b053a05e6ad277c0d1/coregrind/m_syswrap/syswrap-linux.c#L13102-L13120). An FD-number check is not an object-identity or aliasing proof; none of these observations establish complete mediation.
