## Bounded source observation

The AMD64 table maps `pwrite64` to `sys_pwrite64` ([table](https://github.com/unofficial-mirror/valgrind/blob/8d3c8034b87db7b1d47285b053a05e6ad277c0d1/coregrind/m_syswrap/syswrap-amd64-linux.c#L490-L497)). Its [complete PRE body](https://github.com/unofficial-mirror/valgrind/blob/8d3c8034b87db7b1d47285b053a05e6ad277c0d1/coregrind/m_syswrap/syswrap-generic.c#L2774-L2795) sets `SfMayBlock`, annotates the FD/offset and buffer, but contains no `fd_allowed` call. The previously documented normal blocking dispatch uses the separate guest syscall assembly path, not necessarily the generic logger instruction. This observation concerns this wrapper body and normal dispatch; it does not exclude other layers of enforcement.

Conditional example: if a guest knows a live logger FD `H`, that FD names a writable object supporting positional writes, and its buffer, nonnegative offset and all kernel/security-policy checks permit the operation, a `pwrite64(H, ...)` could reach the kernel without this wrapper's ordinary-write FD check. In the selected Linux source, `ksys_pwrite64` obtains the FD and requires `FMODE_PWRITE` before calling `vfs_write` ([688–711](https://github.com/torvalds/linux/blob/8bb7eca972ad531c9b149c0a51ab43a417385813/fs/read_write.c#L688-L711)); `vfs_write` additionally checks write mode, buffer access and verification, then selects a write operation ([574–603](https://github.com/torvalds/linux/blob/8bb7eca972ad531c9b149c0a51ab43a417385813/fs/read_write.c#L574-L603)). Actual success, offset/append behavior, sink type and policy are unknown; pipes and other non-positional sinks do not satisfy the assumed condition. This is not a bypass claim for a policy that denies or otherwise safely mediates `pwrite64`.

As contrast, in this same snapshot the [`writev` PRE wrapper](https://github.com/unofficial-mirror/valgrind/blob/8d3c8034b87db7b1d47285b053a05e6ad277c0d1/coregrind/m_syswrap/syswrap-generic.c#L4769-L4793) checks its FD, and [`pwritev`/`pwritev2`](https://github.com/unofficial-mirror/valgrind/blob/8d3c8034b87db7b1d47285b053a05e6ad277c0d1/coregrind/m_syswrap/syswrap-linux.c#L6212-L6295) call a shared FD-checking helper. [`tee`](https://github.com/unofficial-mirror/valgrind/blob/8d3c8034b87db7b1d47285b053a05e6ad277c0d1/coregrind/m_syswrap/syswrap-linux.c#L6685-L6697) checks both FDs and [`copy_file_range`](https://github.com/unofficial-mirror/valgrind/blob/8d3c8034b87db7b1d47285b053a05e6ad277c0d1/coregrind/m_syswrap/syswrap-linux.c#L13102-L13129) checks input and output FDs. Checks against descriptor numbers alone do not prove object identity or complete mediation. [`open_by_handle_at`](https://github.com/unofficial-mirror/valgrind/blob/8d3c8034b87db7b1d47285b053a05e6ad277c0d1/coregrind/m_syswrap/syswrap-linux.c#L6058-L6082) checks the resulting FD in POST, not proof that every possible object alias is excluded.
